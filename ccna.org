* Day One - Networking Devices
** What is a network.
- A network is a digital telecommunications network that allows nodes to share resources.
- Client: Device that accesses a service made available by a server.
- Server: Device that provides functions or services for clients.
  - Note: The same device can be a client in some situations and a server in others.
*** Switches (L2)
- Provide connectivity to hosts within the same LAN.
- Have many network interfaces for hosts to connect to.
- Do not provide connectivity between LANs.
- Ex: Cisco Catalyst 9200, Catalyst 3650.
*** Routers (L3)
- Have fewer network interfaces than switches.
- Are used to provide connectivity between LANs.
- Are used to send data over the internet.
- Ex: Cisco ISR 1000, ISR 900, ISR 400.
*** Firewalls
- Specialty security devices that control traffic entering/exiting a network.
- Can be placed inside or outside of a network.
- Monitor and control traffic based on configured rules.
- Are known as "Next-Generation Firewalls" when they include advanced filtering capabilities.
- Host-Based firewalls are software applications that filter traffic entering
  and exiting a host machine.
- Ex: Cisco ASA (Adaptive Security Appliance)5500-X, Firepower 2100. (Both Next-Gen)

* Day Three - OSI Model and TCP/IP Suite
** What is a networking model?
- Networking models categorize and provide a structure for networking protocols and standards.
** OSI Model
- Open Systems Interconnection Model.
- Conceptual model taht categorizes and standardizes the different functions in a network.
- Created by ISO.
- Functions are divided into 7 Layers.
- As data moves from the top layer downward the process is called "Encapsulation".
- As data moves from the bottom latyer upward the process is called de-encapsulation.
- When interactions occur on the same later, it is called same-layer interaction.
*** Upper Laters (Application, Presentation, Session)
- Network engineers don't usually work with the top 3 layers.
- Applications developers work with the top layers of the OSI model to connect
  their applications over networks.
*** Mnemonic
- All People Seem To Need Data Processing
*** Application
- Layer closest to end user.
- Interacts with software applications.
- HTTP/HTTPS are Layer 7 protocols.
- Functions include:
  - Identifying communication partners.
  - Syncronizing communication.
*** Presentation
- Translates data to the appropriate format (between Application and Network formats).
*** Session
- Controls sessions between communicating hosts.
- Establishes, manages, and terminates connections between local application and
  remote application.
*** Transport
- Segments and reassembles data for communication between end hosts.
- Breaks large pieces of data into smaller segments which can be more easily sent over the network and are less likely to cause transmission problems if errors occur.
- Provides Host-To-Host communication.
- When Data from Layer 7-5 arrives, it receives a Layer 4 header in the Transport layer.
- << Data + L4 Header >> (Segment)
*** Network
- Provides connectivity between hosts on different networks (ie: outside of a LAN).
- Provides logical addressing (IP Addresses).
- Provides path selection between source and destination.
- Routers operate at Layer 3.
- When Data and the Layer 4 header arrive in the network layer, it receives a Layer 3 header.
- << Data + L4 Header + L3 Header >> (Packet)
*** Data Link
- Provides Node-To-Node connectivity and data transfer.
- Defines how data is formatted for transmission over physical medium.
- Detects and possibly corrects Layer 1 (Physical) errors.
- Uses L2 Addressing.
- Switches operate at L2.
- <<L2 Trailer + Data + L4 Header + L2 Header >> (Frame)
*** Physical
- Defines physical characteristics of the medium used to transfer data between devices; Voltage levels, maximum transmission distances, physical connectors, cable specs.
- Digital bits are converted into electrical or radio signals.
- All of the information in section 2 is related to the Physical Layer.
*** Protocol Data Units (PDU)
| OSI Layer # | PDU Name | Protocol Data Added    |
|-------------+----------+------------------------|
|       7 - 5 | Data     | Data                   |
|           4 | Segment  | Layer 4 Header         |
|           3 | Packet   | Layer 3 Header         |
|           2 | Frame    | Layer 2 Trailer/Header |
|           1 | Bit      | 0/1 Transmission       |
- << L2 Trailer + Data + L4 Header + L3 Header + L2 Header >>
** TCP/IP Suite
- Conceptual model and set of communication protocols used on the inernet and other networks.
- Known as TCP/IP for the foundation protocols of the suite.
- Developed by U.S.D.O.D. through DARPA.
- Similar structure to OSI model, with fewer layers.
- Model most commonly used in modern networks.
- Application, Transport, Internet, Link.

* Day Five - Ethernet LAN Switching (Part 1)
** Data Link (L2)
- Provides node-to-node connectivity and data transfer (PC to switch, switch to
  router, router to router).
- Defines how data is formatted for transmission over a physical medium (UTP, Fiber).
- Detects and (possibly) corrects Physical Layer errors.
- Users Layer 2 addressing.
- Switches operate at Layer 2.
** LAN
- Network contained in relatively small area.
- Routers are used to connect separate LANS.
** Ethernet Frame
- Ethernet Trailer | Packet | Ethernet Header
- Header contains five fields:
  - Field(bytes): Preamble(7) | SFD(1) | Destination(6) | Source(6) | Type(2) |
- Trailer contains single field.
  - Field(bytes): FCS - Frame Check Sequence (4).
- 26 bytes (header + trailer)
*** Preamble
- Length: 7 bytes, 56 bits.
- Alternating 1's and 0's.
- 10101010 * 7
- Allows devices to syncronize their receiver clocks.
*** SFD (Start Frame Delimiter)
- Length: 1 byte (8 bits).
- 10101011
- Marks end of the preamble and beginning of the rest of the frame.
*** Destination and Source
- Later 2 Address
- Indicates devices sending and receiving frame.
- MAC = Media Access Control 6 byte (48-bit) address of physical device.
*** Type/Lenhth
- 2 bytes (16-bit) field.
- Value of 1500 of less in this field indicates length of encansulated packet in bytes.
- Value of 1536 or greater in this field type of encapsulated packet and length
  is determined by other methods.
- IPv4 = 0x0800 (hexadecimal) = 2048 in decimal.
- IPv6 = 0x86DD (hexadecimal) 34525 in decimal.
- Layer 3 protocol used in the encapsulated packet, which is almost always IPv4 or IPv6
*** Trailer
- Frame Check Sequence.
- 4 bytes (32 bits) in length.
- Detects corrupted data by running cyclic redundancy check algo over received data.
** MAC Addresses
- 6 byte 48-bit physical addresses assigned to device when manufacturered.
- Burned into NIC.
- Globally unique.
- First three bytes are Organizationally Unique Identifier (OUI).
- Last 3 byes are unique to the device itself.
- Written as 12 hexadecimal characters.
*** MAC Table
- Each switch stores a dynamically learned MAC table, using the source MAC
  addresses of received frames.
- When a switch doesn't know the destination MAC address of a frame (unknown unicast frame), it is forced to flood the frame.
- When a destination MAC address is recognized by an entry in the MAC table, the frame is
  forwarded to the destination.
- Dynamic MAC addresses are removed from the MAC table after 5 minutes of inactivity.

** ARP (Address Resolution Protol)
- When a PC wants to send a packet to a destination with a known IP Address but unknown MAC address, it sends an ARP Request to learn that destinations MAC Address.
- Consists of Two messages:
  - ARP Request (Source Message)
  - ARP Reply (Destination Message)

- ARP Reply Frame Contents:
  - Source IP
  - Destination IP
  - Source MAC
  - Destination MAC Address
  - Known Unicast Frame - Sent only to the host that sent ARP Request.

- Network utility used to test reachability.

- Uses to message:

** Full/Half Duplex
- Half Duplex
  - Device cannot send/receive data at the same time. If it is receiving a
    frame, it must wait before sending a frame.
- Full Duplex
  - Device can send / receive data at the same time.
  - Most modern switches support full duplex.
*** Duplex and Collision Detection
- Half duplex is used almost nowhere.
- In the past, when multiple packets were received by a hub, the hub would flood
  the connection with frame data, causing a collision on the interface, and
  hosts would not receive the frame intact. All devices connected to a hub are
  called a Collision Domain.
**** CSMA/CD
- Carrier Sense Multiple Access with Collision Detection
  - Before sending frames, devices listen to the collision domain until they
    detect that the other devices are not sending.
  - If a collision occurs, the device sends a jamming signal to inform the other
    devices that a collision has occurred.
  - Each device waits a random period of time before sending frames again.
  - the process repeats.
  - Hubs are L1 Devices.
  - Switches are L2 Devices.
*** Speed/Duplex Autonegotiation
- Interfaces that can run at different speeds have a default setting of SPEED
  AUTO and DUPLEX AUTO.
- Interfaces advertise their capabilities to the neighboring device and
  negotiate the best speed and duplex settings they are both capable of.
- Collissions will occur if autonegotiation is disabled.
- The switch will try to send at the speed the other device requires, if it
  fails to send at that speed, it will use the slowest supported speed.
- Duplex: If the speed is 10 or 100Mbps the switch will use half duplex, if the
  speed is 1000Mbps or greater, it will use full duplex.
** Interface Counters and Errors
- SW#1show interfaces # Shows error stats at borrom

- Giants: Frames that are larger than the maximum frame size (1518 bytes).
- CRC: Frames that have an inforrect format.
- Input Errors: Total of various counters.
- Output Errors: Frames the switch tried to send, but failed due to an error.
* Day Ten - IPv4 Header
** IPv4 Header
- Used at L3 to help send data between devices on separate networks.
- This is known as routing.
- the IPv4 header is used to encapsulate a TCP or UDP segment.
*** Fields
- Version (4 Bits)
- IHL (4 Bits)
- DSCP (6 Bits)
- ECN (2 Bits)
- Total Length 16 bits
- Identification 16 bits
- Flags (3 Bits)
- Fragment Offset (13 Bits)
- Time to Live (8 Bits)
- Protocol (8 Bits)
- Header Checksum (16 Bits)
- Source Address (32 Bits)
- Destination Address (32 Bits)
- Options (320 Max Bits)
**** Version
- Length: 4 Bits
- ID's version if IP being used (IPv4 or IPv6)
  - IPv4 = 0100 in Binary (Decimal 4)
  - IPv6 = 0110 in Binary (Decimal 6)
**** Internet Header Length (IHL)
- Length is 4 Bits.
- Final field of IPv4 header (Options) is variable in length so this field is
  necessary to indicate the total length of the header.
- ID's the length of the header in 4-Byte Increments.
- Minimum value is 5 (5 * 4-bytes = 20 bytes) - Empty OPTIONS field.
- Maximum value is 15 (15 * 4-bytes = 60 bytes)
**** DSCP (Differentiated Services Code Point)
- Length is 6 Bits
- Used for QoS (Quality of Service)
- Used to prioritize delay-sensitive data (streaming voice, video, etc.)
**** ECN (Explicit Congestion Notification)
- Length of 2 Bits.
- Provides end-to-end notification of network congestion without dropping
  packets.
- Optional feature that requires both endpoints, as well as the underlying
  network infrastructure to support it.
**** Total Length
- 16 Bits
- Indicates total length of the packet (L3 Header + L4 Segment)
- Measured in bytes (not 4-byte increments like IHL)
- Minimum value of 20 Bytes (IPv4 Header with no encapsulated data)
- Maximum value of 65,535
**** Identification
- Length is 16 bits.
- If a packet is fragmented due to being too large, this field is used to
  identify which packet the fragment belongs to.
- All fragments of the same packet will have their own IPv4 header with the same
  value in this field.
- Packets are fragmented if larger than MTU (Maximum Transmission Unit)
- MTU is usually 1500 bytes (Max size of Ethernet Frame)
- Fragments are reassembled by the receiving host.
**** Flags
- Length is 3 bits.
- Used to control/identify fragments
- Bit 0: Reserved, always set to 0.
- Bit 1: Don't Fragment (DF bit), used to indicate a packet that should not be
  fragmented.
- Bit 2: More Fragments (MF bit) set to 1 if there are more fragments in the
  packet, set to 0 for the last fragment or no fragments.
**** Fragment Offset
- Length is 13 bits
- Used to indicate the position of the fragment within the original,
  unfragmented packet.
- Allows fragmented packets to be reassembled even if the fragments arrive out
  of order.
**** Time To Live (TTL)
- Length is 8 bits
- A router will drop a packet with a TTL of 0
- Used to prevent infinite loops
- Originally designed to indicate a packets maximum lifetime in seconds.
- In practice, indicates a hop count. Each time the packet arrives at a router,
  the router descreases the TTL by 1.
- Recommended default TTL is 64.
**** Protocol
- Length is 8 bits.
- Indicates the protocol if the encapsulated L4 PDU
- Value of 1: ICMP
- Value of 6: TCP
- Value of 17: UDP
- Value of 89: USPF (Dynamic Routing Protcol)
**** Header Checksum
- Length of 16 bits.
- Calculated checksum to check for errors in the IPv4 header.
- when a router receives a packet, it calculates the checksum of the header and
  compares it to the one in this field of a header.
- If they do not match, the router drops the packet.
- Used to check for errors in the IPv4 header only.
- IP relies of the encapsulated protocol to detect errors in the encapsulated
  data.
- Both TCP and UDP have their own checksum fields to detect errors in the
  encapsulated data.
**** Source / Destination
- Length of 32 bits each.
- Source IP = IPv4 Address of the sender of the packet.
- Destination IP = IPv4 Address of the intended receiver of the packet.
**** Options
- Length is 0-320 bits
- Optional / Rarely used.
- If the IHL field is greater than 5, it means Options are present.
